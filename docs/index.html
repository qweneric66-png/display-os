PDD 店铺商品数据自动采集平台

一个把 PDD 店铺商品采集从脚本执行升级为可视化任务平台的项目，覆盖登录确认、商品列表、详情 SKU、OCR 价格识别、Excel 模板交付和任务审计。

                01业务起点

                先定义业务终态

                不把脚本结束当成交付完成，先明确用户最终能确认什么。

                问题

                代码跑通、接口返回或文件生成，只能证明技术动作完成。

                判断与行动

                先写业务终态验收句，再反推输入、处理、异常和人工确认。

                验证

                商品发布回查平台状态；工程交付同时检查重建、位置、截图和保存。

                适用网页采集、商品发布、工程建模

                02事实基础

                把输入变成可核验事实

                保留来源并区分事实、推断和待确认项，不让猜测进入交付。

                问题

                网页、截图、OCR、表格和模型输出可能互相冲突。

                判断与行动

                为业务对象建立稳定身份，记录来源、冲突、缺失和证据状态。

                验证

                商品、SKU、项目资产和工程参数按对象组织，证据不足时保留边界。

                适用OCR、商品资料、RAG、CAD 参数

                03责任边界

                让 AI 只做适合的判断

                AI 生成候选，规则检查资格，人工确认风险，工具负责执行。

                问题

                候选内容未经判断就执行，会让结论超出真实证据。

                判断与行动

                用项目身份和证据状态约束候选，低置信度与高风险动作保留人工确认。

                验证

                四个项目呈现不同能力组合，未验证内容不包装成确定结论。

                适用项目分析、内容生成、商品发布、参数确认

                04可恢复流程

                让长任务可以恢复

                按业务对象保存状态，异常定位到步骤，修复后只重跑失败部分。

                问题

                页面出现结果，不代表任务在切换或重启后还能继续。

                判断与行动

                设计暂停、恢复、失败和回查状态，用检查点与幂等支持局部重试。

                验证

                项目切换与重启后资产保持隔离，成功结果不会被旧状态覆盖。

                适用批量采集、AI 审核、内容生成、文件交付

                05失败与评测

                用反例证明结果

                区分实现、测试、现场运行与业务终态，让结论不超过证据。

                问题

                页面能打开或测试通过，只能证明局部成立，真实反例仍可否决成功。

                判断与行动

                分层记录证据，复测失败样本，把未验证项单独标出。

                验证

                UI 已通过桌面和窄屏检查；长期稳定性与业务指标仍按边界表达。

                适用AI 输出、数据平台、工程产物、运营工作台

                06经验复用

                把失败变成规则资产

                把反例转成检查、规则和回归测试，阻止同类问题再次出现。

                问题

                同类偏差会跨项目重复出现，单次修复无法阻止下一次漂移。

                判断与行动

                沉淀问题边界、处理步骤、失败样本、证据要求和验收标准。

                验证

                本地 Skill 与跨项目 UI 门禁可被调用、检查和持续修订。

                适用项目分析、质量治理、协作交付、能力成长

                07可追溯交付

                让结论可以复查

                用备份、版本、根因和验证记录，把经验从记忆变成可复现事实。

                问题

                需求和修复只留在聊天里，无法判断历史结论是否仍然有效。

                判断与行动

                保留前置备份、修改原因、影响范围、验证结果和风险。

                验证

                任务归档与成长文档联动，页面判断能回到具体版本事实。

                适用Bug 修复、架构升级、UI 改版、交付复盘

                08协作边界

                分开共享资产与本机状态

                共享代码、规则和文档，隔离账号、路径、缓存与运行状态。

                问题

                同步文件不等于另一台机器已经具备相同运行条件。

                判断与行动

                区分可复用资产与机器差异，恢复后重新检查入口、依赖和环境。

                验证

                本地服务与分享展示已有明确边界，跨设备运行仍以目标环境复核为准。

                适用GitHub 分享、双机开发、现场交付、团队协作
